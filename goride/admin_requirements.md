# GoRide Laravel Admin Backend - Requirements & Implementation Plan

This document outlines the complete specifications for building the GoRide admin dashboard using Laravel. It details all the features, controls, and data points required to fully manage the existing Expo React Native mobile application.

## 👥 Role-Based Access Control (RBAC)

The dashboard requires two distinct roles with strict permission boundaries:

### 1. Super Admin (Full Access)
* Has unrestricted access to all modules.
* Can manage (create/edit/delete) other Admins and Moderators.
* Can configure global application settings (pricing, dispatch radius, timeouts).
* Can view platform-wide financial reports and analytics.
* Can manage system-wide promo codes and broadcast notifications.

### 2. Moderator (Operational Access)
* Focuses on day-to-day operations and customer support.
* **Can Do:** Verify driver documents, handle support chat tickets, review withdrawal requests, monitor active rides/deliveries.
* **Cannot Do:** Delete user accounts, modify global pricing/dispatch settings, create/manage admin accounts, view total platform revenue.

## 📱 What Can Be Controlled (Feature Breakdown)

Based on the mobile app's architecture, here is the exact list of modules and features the Laravel backend must implement to fully control the app:

### 1. User Management (Riders)
* **View Users:** List all registered riders with their details (Name, Phone, Email, Avatar).
* **Action:** Suspend/Ban users (temporarily or permanently).
* **View History:** See a rider's full ride and delivery history, including cancelled requests.
* **Wallet Management:** View current wallet balance, transaction history, and manually credit/debit wallets (e.g., for refunds).

### 2. Driver Management & Verification
* **View Drivers:** List all registered drivers and filter by status (Pending, Verified, Suspended).
* **Document Verification (Crucial):**
  * Review uploaded documents: Driver's License, NIN Slip, Vehicle Particulars, Vehicle Exterior photos, and Selfie.
  * **Action:** Approve or Reject verification.
  * **Trigger:** Approving/Rejecting should trigger a `profile_approved` or `profile_rejected` push notification to the driver.
* **Vehicle Info:** View vehicle make, year, color, and license plate.
* **Driver Courier Mode:** Define or restrict what a driver can do based on vehicle type (e.g., motorbikes restricted to courier only, cars for rides + courier).
* **Action:** Suspend/Ban drivers.

### 3. Rides & Deliveries (Monitoring)
* **Live Tracking:** View a feed of active rides and deliveries.
* **Ride History:** View all completed and cancelled rides with timestamps, pickup/drop-off locations, assigned driver, and fare details.
* **Delivery History:** View all package deliveries, including sender/receiver details, package category, and status phases (`picked_up`, `in_transit`, `delivered`).
* **Action:** Manually cancel a stuck ride or delivery and issue refunds if necessary.

### 4. Financials & Withdrawals
* **Driver Earnings:** Monitor driver wallet balances and total earnings.
* **Withdrawal Requests:** 
  * Drivers request payouts from the app.
  * **Action:** Moderators review pending requests. Approve, Reject, or Mark as Completed.
  * **Trigger:** Action triggers `withdrawal_approved`, `withdrawal_rejected`, or `withdrawal_completed` notifications.
* **Transaction Logs:** View system-wide logs for every wallet credit and debit.

### 5. Live Support Chat
* **Ticket Management:** View all open support tickets generated by users and drivers.
* **Context:** Tickets include Reference IDs linking them to specific Rides, Deliveries, or Transactions.
* **Chat Interface:** Real-time chat interface to reply to users.
* **Trigger:** When an admin sends a message, it triggers a `message` push notification with the payload `{"screen": "support-chat"}` so the user can tap it and instantly open the chat.
* **Action:** Mark tickets as "Resolved" or "Closed".

### 6. Notifications & Marketing
* **Broadcast Notifications:** Send manual push notifications to all users, all drivers, or specific individuals (e.g., `admin_announcement`, `system`).
* **Promo Codes & Coupons:**
  * Create discount codes (percentage or fixed amount).
  * Set expiry dates and usage limits.
  * **Trigger:** Send a `promo` or `coupon` push notification to users when a new campaign launches.

### 7. Global Application Settings (Admin Only)
* **Dispatch Settings:**
  * **Dispatch Radius:** Adjust the maximum search radius for matching riders to drivers (e.g., 5km, 10km).
  * **Acceptance Timeouts:** Set how long a driver has to accept a ride before it expires or gets passed to the next driver.
* **Parcel Categories:** Manage the dynamic list of allowed package types and weights that show up in the user's delivery request screen.
* **Platform Fees:** Configure the commission percentage the platform takes from driver earnings.

## 🚀 Perfect Prompt for Building the Laravel Admin Backend

If you want to pass a prompt to an AI or a developer to start building this Laravel backend, you can copy and paste the following:

> **Prompt:**
> "I need to build a comprehensive Admin Dashboard using Laravel (PHP) and Livewire/Filament (or Vue/React/Inertia) to manage a React Native Expo ride-sharing and package delivery app. The backend will interact heavily with a Supabase PostgreSQL database.
> 
> **Role-Based Access Control:**
> Implement two roles using Spatie Permissions:
> 1. **Super Admin**: Full access to all settings, revenue metrics, and admin management.
> 2. **Moderator**: Operational access to verify driver documents, answer support tickets, review withdrawal requests, and monitor rides, but restricted from global settings and user deletion.
>
> **Core Modules Required:**
> 1. **Auth & Dashboard:** Separate landing/login page for admins. Dashboard showing high-level metrics (Active rides, Pending verifications, Pending withdrawals).
> 2. **Driver Verification System:** Interface to review driver uploads (License, NIN, Vehicle photos) and a toggle to Approve/Reject, which updates the Supabase `verification_status` and triggers a notification.
> 3. **User & Driver Management:** Data tables to view, suspend, or ban riders and drivers. Ability to view their wallet balances and transaction history.
> 4. **Live Support Chat Interface:** A ticketing system where admins can chat in real-time with users. It must connect to the `support_tickets` and `support_messages` tables. When an admin replies, it should trigger a webhook or event to send a push notification to the user.
> 5. **Financials:** Interface to approve/reject driver withdrawal requests.
> 6. **Global Settings:** Form to manage dynamic app variables: Dispatch Radius, Ride Acceptance Timeout, Commission Fees, and Parcel Categories.
> 7. **Notification Center:** A tool to compose and broadcast custom push notifications (Announcements, Promos) to specific roles or all users.
>
> **Technical Requirements:**
> * Connect to an existing Supabase PostgreSQL database.
> * Use Laravel Events/Listeners or Supabase webhooks to trigger push notifications via the Expo Push API when statuses change (e.g., document approved, withdrawal processed, support message sent).
> * The UI must be premium, responsive, and data-dense, suitable for high-volume moderation."
